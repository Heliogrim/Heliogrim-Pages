## Target

- **Visual scripting**: graphs compile to readable, deterministic C++ with source maps, built like hand-written code; an interpreted path for iteration in the editor; the same graph compiler serves materials (to ASL), particles, animation graphs and procedural generators.
- **HMR**: game modules reload in the editor and in a running game with state preserved; two tiers, function patching for the inner loop and module swap with reflection-driven migration for structural changes.

## Research summary

- Live++ (verified docs): recompiles changed translation units from PDB-recovered command lines, links a patch DLL, swaps code atomically at a frame boundary; needs `/Z7` or `/Zi`, `/FUNCTIONPADMIN`, `/OPT:NOREF /OPT:NOICF`, `/DEBUG:FULL`, and for clang `-fms-hotpatch -ffunction-sections -gcodeview -mno-constructor-aliases`; no LTO; structural changes (layout, vtable) are not migrated, the user serialises, destroys and recreates in pre- and post-patch hooks; stack objects cannot be migrated; thread-local storage and global initialisers have documented limits. Pricing page verified on 2026-11-07: about EUR 12 per month individual, EUR 20 business, 30-day trial (recheck before budgeting).
- cr.h keeps state across reloads through `CR_STATE` section tagging; RuntimeCompiledC++ migrates through its object serialisation; Kitsune (OOPSLA 2012) generates state transformers from specifications and Ksplice (EuroSys 2009) usually needs none (abstracts verified).
- Nativisation history (search summaries only): Unreal deprecated Blueprint nativisation in 4.27 and removed it in 5.0, Godot discontinued VisualScript with 4.0; reported reasons are build cost, fragility and small gains. Graph compilation: dataflow plus control flow, typed IR, deterministic output, `#line` source maps to node IDs.

## Guidance

### S48 Hot module reload

- **Module boundary**: a game project builds one or more DLL modules against an exported engine SDK (S53); the engine owns all allocators and the DLL never owns memory that outlives it (S08); types are registered from an explicit module init with content-hash identities (S09); no function pointers or vtables of module code are held by the engine across a reload except through handles that the reload re-resolves.
- **Tier 1, function patching**: set the compiler and linker flags Live++ requires in a `HotReload` build profile (they are also what an in-house patcher needs); evaluate Live++ (commercial) against an in-house patcher based on the same flags; measure reload latency on a real module.
- **Tier 2, module swap**: on a structural change, the editor serialises all instances of module-owned types through S01 into a migration buffer, unloads, loads the new DLL, re-registers types, runs upcasters for changed layouts, hydrates. Archetype regions relocate through the relocation barrier from #80.
- Crash dumps record patch identities (S06); the deterministic replay (S59) treats a reload as a barrier.

### S47 Visual scripting compiler

- **Graph IR**: typed nodes with exec and data pins; validation and type inference with diagnostics on node spans (S05); lowering to a structured typed IR; emitters to C++ (game logic, generators), ASL (materials), and the particle and animation node programs.
- **Output**: deterministic file content (sorted iteration, stable IDs, fixed formatting), `#line` mapping to node IDs, golden-tested; generated files are write-only and regenerated by the build.
- **Iteration path**: an interpreter over the same IR for immediate feedback in the editor; emission for shipping and for hot reload through S48. This avoids the Blueprint-nativisation trap of making emission mandatory for every edit.
- **Build**: generated C++ lives in the game module; Ninja incremental builds are measured per graph change.

## Done when

- A changed function in a game module reloads in the running editor within the stated latency with no state loss; a changed component layout reloads with instances migrated and a diagnostic for any field that could not be mapped.
- A visual script compiles to C++ that passes clang-tidy, runs identically to the interpreter on a fixture, and maps a runtime diagnostic back to its node.
- A material graph emits ASL that compiles through S11.
