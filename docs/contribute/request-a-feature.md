# Request a Feature or Task

<a class="hg-btn primary" href="https://github.com/Heliogrim/Heliogrim-Engine/issues/new?template=2-feature_request.yml">Request a feature</a>
<a class="hg-btn" href="https://github.com/Heliogrim/Heliogrim-Engine/issues/new/choose">Other issue types</a>

The first button opens the engine repository's feature request form. Tasks have no form of their own; maintainers create them on the [project board](project-links.md).

## Feature or task

| | Feature request | Task |
|--|-----------------|------|
| Starts from | A problem you have | A piece of work that is already agreed |
| Outcome | Discussion, then maybe a task | Done when its checklist is done |
| Written by | Anyone | Usually a maintainer or the person doing it |

## Writing a good request

- **Lead with the problem**, not the solution. "Level streaming stalls the frame" beats "add a thread pool".
- **Say what you tried.** Alternatives and workarounds show whether the engine already covers the need.
- **Check the docs.** The [architecture](../architecture/index.md) section may already explore it, and the [timeline](../architecture/timeline.md) shows what is blocked on what.
- **Keep it small.** Large requests are split into tasks on the board.

If the request needs a design decision, it will be redirected to a [proposal](propose-a-change.md).
